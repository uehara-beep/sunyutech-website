# SSH の有効化と鍵の登録（サーバー担当者向け）

**宛先**: uehara さん
**目的**: サイト更新の自動化（issue #30）を可能にする
**最終更新**: 2026-09-02

---

## なぜこれをやるのか

現在、サイトの更新はファイルを手でアップロードして行っています。この方法には
次の問題があります。

- 前回何をどう置いたか、記録が残らない
- `contact-config.php`（お問い合わせフォームの設定）を誤って消すと、
  問い合わせが届かなくなる
- 更新のたびに uehara さんの手が空いている必要がある

SSH を有効にすると、**GitHub 側で変更が承認された時点で、サーバーに自動で
反映される**ようにできます。誰が・いつ・何を更新したかも自動で記録されます。

作業は**この1回だけ**です。以降は不要になります。

---

## 前提

- お名前.com レンタルサーバー **RSプラン** をご利用中
- お使いのパソコンは Windows / Mac のどちらでも構いません

> RSプランは SSH に対応しています。ただし当方でご契約内容を確認できないため、
> **手順1でメニューが見つからない場合はその時点でお知らせください。**
> 別の方法（FTPによる自動化）に切り替えます。

---

## 🔑 はじめに: 鍵について

この手順では「鍵」を2つ作ります。

| | 役割 | 扱い |
|---|---|---|
| **公開鍵** (`.pub` が付く方) | サーバーに登録する | 人に見せても問題ありません |
| **秘密鍵** (`.pub` が付かない方) | 手元に保管する | **絶対に他人に渡さないでください** |

> ### ⚠️ 秘密鍵は誰にも送らないでください
>
> 開発担当（watanabe さん）にも、このプロジェクトのAIにも送る必要はありません。
> メール・チャット・GitHub のどこにも貼らないでください。
>
> **秘密鍵を持っている人は、サーバーに自由にログインできます。**
> パスワードと同じか、それ以上に重要なものとお考えください。
>
> 手順5で GitHub に登録する場面がありますが、そこは秘密鍵を安全に保管する
> 専用の場所（Secrets）で、登録後は誰も中身を見られなくなります。

---

## 手順1: SSH を有効にする

1. お名前.com レンタルサーバーの **コントロールパネル** にログイン
2. メニューから **「SSH」** に関する項目を探す
   （「SSH設定」「SSHアカウント」などの名称です）
3. 対象のドメイン（sunyutech.jp）について SSH を **有効** にする
4. 表示される次の情報をメモしてください

| 項目 | 備考 |
|---|---|
| ホスト名 | 画面に表示されるサーバーのアドレス |
| ユーザー名 | 画面に表示されるアカウント名 |
| ポート番号 | 22 以外が指定されていることがあります |

> **画面に出ている値をそのまま控えてください。** 形式はプランや
> 契約時期によって異なるため、こちらでは例を示せません。
> 表示が見当たらない場合は、画面の写しをお送りいただければ判断します。

> **メニューが見つからない場合**は、探すのをやめてお知らせください。
> プランによって名称や場所が異なります。こちらで調べます。

## 手順2: 鍵を作る

お使いのパソコンで作業します。

### Mac の場合

「ターミナル」アプリを開いて、次を**1行ずつ**実行します。

```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
ssh-keygen -t ed25519 -f ~/.ssh/sunyutech_deploy -C "sunyutech-deploy"
```

1行目は鍵を置くフォルダを用意するものです。すでにあれば何も起きません。
これを飛ばすと `No such file or directory` というエラーになります。

途中で `Enter passphrase` と聞かれます。**何も入力せず Enter を2回**押してください。
（自動化で使うため、パスフレーズ無しにします）

### Windows の場合

「PowerShell」を開いて、次を**1行ずつ**実行します。

```powershell
New-Item -ItemType Directory -Force -Path $env:USERPROFILE\.ssh
ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\sunyutech_deploy -C "sunyutech-deploy"
```

1行目は鍵を置くフォルダを用意するものです。すでにあれば何も起きません。

### できるもの

| ファイル | 中身 |
|---|---|
| `sunyutech_deploy` | **秘密鍵**（他人に渡さない） |
| `sunyutech_deploy.pub` | **公開鍵**（サーバーに登録する） |

## 手順3: 公開鍵をサーバーに登録する

### 公開鍵の中身を表示する

**Mac**
```bash
cat ~/.ssh/sunyutech_deploy.pub
```

**Windows**
```powershell
Get-Content $env:USERPROFILE\.ssh\sunyutech_deploy.pub
```

`ssh-ed25519 AAAA...` で始まる1行が表示されます。これを丸ごとコピーします。

### コントロールパネルに貼る

手順1の SSH 設定画面に「公開鍵の登録」「公開鍵を追加」といった欄があります。
そこにコピーした1行を貼り付けて保存してください。

> 「公開鍵を生成する」というボタンがある場合もあります。その場合は
> サーバー側で鍵を作って秘密鍵をダウンロードする形になります。
> **どちらの方式でも構いません。** サーバー側で生成した場合は、
> ダウンロードした秘密鍵を手順2で作ったものの代わりに使います。
>
> **ただしパスフレーズ（鍵のパスワード）は設定しないでください。**
> 入力を求められた場合は空のまま進めます。
>
> パスフレーズ付きの鍵は、手順4の接続確認では**その場で入力できるため
> 成功してしまいます**。自動更新の仕組みは入力できないので、
> 後になって「接続確認は通ったのに動かない」という分かりにくい
> 失敗の仕方をします。

## 手順4: つながるか確認する

**Mac**
```bash
ssh -i ~/.ssh/sunyutech_deploy -p ポート番号 ユーザー名@ホスト名
```

**Windows**
```powershell
ssh -i $env:USERPROFILE\.ssh\sunyutech_deploy -p ポート番号 ユーザー名@ホスト名
```

ポート番号・ユーザー名・ホスト名は、手順1でメモしたものに置き換えてください。

初回は次のように聞かれます。`yes` と入力してください。

```
Are you sure you want to continue connecting (yes/no)?
```

**接続できたら**、次を実行して現在地とフォルダの中身を確認します。

```bash
pwd
ls
```

`pwd` はいまどこにいるかを表示します。`ls` で見えるフォルダの中に
`public_html` があるはずです。あれば次で中身を確認できます。

```bash
ls public_html/sunyutech.jp/
```

`index.html` などが並べば成功です。`exit` と入力すれば抜けられます。

> **パスの書き方に注意してください。** FTPソフトでは `/public_html/sunyutech.jp/`
> と表示されますが、SSH でログインした直後の位置はその親にあたることが多く、
> 先頭に `/` を付けると「そんなフォルダは無い」と言われます。
> **`pwd` と `ls` で実際の場所を確かめてから進めてください。**
> 見えた内容をそのままお知らせいただければ、こちらで判断します。

### つながらないとき

エラーメッセージを**そのままコピーして**お知らせください。
原因の切り分けはこちらで行います。推測で設定を変えると、
かえって分からなくなります。

## 手順5: GitHub に秘密鍵を登録する

自動更新の仕組みがサーバーにログインできるよう、秘密鍵を GitHub に預けます。

> ここで預ける先は **Secrets** という専用の保管場所です。
> 登録すると画面には二度と表示されず、リポジトリを閲覧するだけの人には読めません。
> 通常のファイルとして置くのとはまったく別の扱いです。
>
> ただし万能ではありません。**このリポジトリに書き込み権限を持つ人は、
> 仕組み上この鍵を取り出せます。** 権限を渡す相手は限ってください。
> 鍵が漏れたと思われる場合は、コントロールパネルで公開鍵を削除すれば
> その鍵は使えなくなります（手順2からやり直しになります）。

### 秘密鍵の中身を表示する

**Mac**
```bash
cat ~/.ssh/sunyutech_deploy
```

**Windows**
```powershell
Get-Content $env:USERPROFILE\.ssh\sunyutech_deploy
```

`-----BEGIN OPENSSH PRIVATE KEY-----` から
`-----END OPENSSH PRIVATE KEY-----` までを、**改行も含めて丸ごと**コピーします。

### 登録する

1. https://github.com/uehara-beep/sunyutech-website を開く
2. **Settings** → 左メニューの **Secrets and variables** → **Actions**
3. **New repository secret** を押して、次の4つを1つずつ登録

| Name | Secret に入れる値 |
|---|---|
| `DEPLOY_SSH_KEY` | 秘密鍵の全文 |
| `DEPLOY_HOST` | ホスト名 |
| `DEPLOY_USER` | ユーザー名 |
| `DEPLOY_PORT` | ポート番号 |

登録が終わったら、**手元の秘密鍵ファイルは消さずに保管**してください
（再登録が必要になったときに使います）。

## よくある詰まり

### 「Permission denied (publickey)」と出る

公開鍵の登録がうまくいっていない可能性が高いです。
コントロールパネルで登録済みの鍵を確認し、手順3で表示した内容と
一致しているか見てください。改行が混ざって2行になっていることがあります。

### ポート番号が分からない

`22` を試して駄目なら `10022` を試してください。
それでも駄目な場合はコントロールパネルの SSH 設定画面に記載があります。

### コマンドを打つのが不安

**無理に進めないでください。** この作業を飛ばしても、
これまでどおり手作業での更新は続けられます。
自動化は「あると楽になる」ものであって、必須ではありません。
