# お問い合わせフォーム 設置手順（サーバー担当者向け）

**宛先**: uehara さん
**対象**: PR #22 でマージされるお問い合わせフォーム
**最終更新**: 2026-08-31

新しいお問い合わせフォームは、**サイトをアップロードしただけでは動きません。**
サーバー上での設定が1回だけ必要です。この手順書のとおりに進めてください。

所要時間はおよそ15分です。Turnstile（ボット対策）を後回しにする場合は10分程度です。

---

## 0. 先に確認していただきたいこと

### PHP のバージョン（これだけは事前確認をお願いします）

このフォームは **PHP 8.0 以上**が必要です。7.x の場合、フォームだけでなく
**設置したページ全体が真っ白（500エラー）になります。**

お名前.com はディレクトリ単位で PHP のバージョンを選べるため、古い設定が
残っている可能性があります。次のどちらかで確認してください。

**方法A: コントロールパネルで見る**
お名前.com のレンタルサーバー管理画面 → 「PHP設定」→ 対象ドメインのバージョン表示

**方法B: ファイルを1つ置いて見る**

`phpinfo.php` という名前で以下のファイルを作り、公開ディレクトリにアップロードします。

```php
<?php phpinfo();
```

ブラウザで `https://sunyutech.jp/phpinfo.php` を開くと、一番上に
`PHP Version 8.x.x` と表示されます。

> **確認したら必ずこのファイルを削除してください。**
> サーバーの内部情報が誰でも見える状態になります。

**8.0 未満だった場合**は、設置前に管理画面で 8.1 以上に切り替えてください。
切り替えができない事情がある場合は、その旨をお知らせいただければ
古いバージョンでも動くように作り直します。

### メールアドレスの確認

問い合わせの届き先は、設定ファイルに記入していただきます。

このリポジトリは**公開**されているため、手順書にも設定のひな形にも
実際のアドレスは書いていません。アドレス収集ボットに拾われるのを防ぐためです。
同じ理由で、GitHub の issue や PR にも実アドレスを書かないでください。

## 1. サイトのファイルをアップロードする

ビルド済みの `dist/` の中身を、公開ディレクトリにアップロードします。

> ### アップロードの順序
>
> **`contact.php` と `contact-lib.php` を、HTMLファイルより先に（または同時に）
> アップロードしてください。**
>
> HTMLだけが先に入れ替わると、新しいフォームが古い受け口に送信することになり、
> 訪問者は「入力内容をご確認ください」とだけ表示されて、**どこを直せばよいか
> 分からないまま送信できなくなります**。
>
> 逆の順序（PHPが先）なら問題は起きません。まとめてアップロードするのが確実です。

このとき、次のファイルが含まれていることを確認してください。

| ファイル | 役割 |
|---|---|
| `contact.php` | 問い合わせを受け取る本体 |
| `contact-lib.php` | 上記が使う処理 |
| `contact-config.example.php` | 設定のひな形 |
| `.htaccess` | 設定ファイルを外から見えないようにする |

> **`.htaccess` は隠しファイルです。** FTPソフトによっては既定で表示されず、
> アップロードから漏れます。「隠しファイルを表示する」設定を有効にしてください。

> ### ⚠️ `.htaccess` を上書きする前に必ずお読みください
>
> 現在のサーバーには、すでに `.htaccess` が置かれている可能性があります。
> そこには、www 付きURLの転送、常時HTTPS化、エラーページの指定、
> PHPバージョンの指定などが書かれていることがあります。
>
> **今回のファイルで単純に上書きすると、それらの設定がすべて消え、
> サイト全体が正しく表示されなくなる恐れがあります。**
>
> 手順:
> 1. **そもそもファイルをどこに置くか確認する。** 前回の設置場所が
>    分からない場合は、お名前.com の管理画面でドメインの公開ディレクトリを
>    確認してください（`/public_html/` や `/sunyutech.jp/` などプランにより異なります）
> 2. サーバー上の既存の `.htaccess` をダウンロードして保管する（バックアップ）
> 3. 中身が空、またはファイル自体が無ければ、そのままアップロードしてよい
> 4. 中身がある場合は、**既存の内容を残したまま**、今回の
>    `.htaccess` の中身を末尾に**追記**する
>
> 判断に迷う場合は、既存ファイルの中身をお知らせください。こちらで
> 統合したものをお渡しします。

## 2. 設定ファイルを作る

サーバー上で `contact-config.example.php` を **`contact-config.php`** という名前に
コピーし、中身を編集します。

コピー元のファイルは残しておいて構いません（外からは見えないようになっています）。

```php
<?php
return [
    'mail_to'   => '（問い合わせを受け取るアドレス）',
    'mail_from' => 'no-reply@sunyutech.jp',

    'form_secret' => 'ここにランダムな文字列',

    'turnstile_enabled' => false,
    'turnstile_sitekey' => '',
    'turnstile_secret'  => '',
];
```

### `form_secret` について

いたずら送信を防ぐために使う、パスワードのような文字列です。
**推測されにくい長い文字列**にしてください。他人に教える必要はありません。

SSH が使える場合は、次のコマンドで生成できます。

```bash
php -r "echo bin2hex(random_bytes(32));"
```

SSH を使わない場合は、適当に長い英数字（40文字以上）を手で作っていただいても
問題ありません。意味のある単語は避けてください。

### `mail_from` について

`no-reply@sunyutech.jp` のままにしてください。**訪問者のメールアドレスに
変更しないでください。** 送信元を偽装した形になり、Gmail 側で迷惑メールとして
処理されて届かなくなります。

このアドレスは実在しなくても送信できますが、実在させておく方が確実です。

## 3. 動作を確認する

`https://sunyutech.jp/contact/` を開き、実際に自分で問い合わせを送信してください。

| 確認すること | 期待する結果 |
|---|---|
| 送信ボタンを押す | 「送信しました。担当者よりご連絡いたします。」と表示される |
| 受信用アドレスの受信箱 | 件名「【HP問い合わせ】(お名前)」のメールが届く |
| 迷惑メールフォルダ | **こちらも必ず確認してください** |

### 届いたメールへの返信について

そのまま返信すれば、**問い合わせをくださったお客様に直接届きます**
（返信先が自動で設定されています）。送信元の `no-reply@` には返信しないでください。

## 4. Turnstile を有効にする（任意・後日でも可）

Cloudflare の無料のボット対策です。訪問者に操作を求めないため、
問い合わせのしやすさは変わりません。

**この作業はサーバー上だけで完結します。** サイトの再アップロードは不要です。

1. https://dash.cloudflare.com にログイン
2. 左メニューの「Turnstile」→「サイトを追加」
3. ドメインに `sunyutech.jp` を入力して作成
4. **サイトキー**と**シークレットキー**の2つが表示される
5. `contact-config.php` を次のように書き換える

```php
    'turnstile_enabled' => true,
    'turnstile_sitekey' => '発行されたサイトキー',
    'turnstile_secret'  => '発行されたシークレットキー',
```

6. もう一度フォームから送信して、届くことを確認する

> **3つセットで変更してください。** `turnstile_enabled` だけ `true` にして
> キーが空のままだと、設定エラーとして送信が止まります（黙って壊れるより
> 気づける方が安全なため、そう作ってあります）。

Turnstile を使わない場合も、ハニーポット・送信時間チェック・入力検証・
回数制限の4つの対策は常に動いています。

## 5. 今後サイトを更新するときの注意

**`contact-config.php` を消さないでください。**

このファイルはシークレットキーを含むため、GitHub にも `dist/` にも入っていません。
サーバー上にしか存在しません。

FTPソフトの同期機能には、「アップロード元に無いファイルをサーバーから削除する」
（ミラーリング／完全同期）という設定があります。**これを使うと
`contact-config.php` が消え、問い合わせが届かなくなります。**

- 同期の設定を「追加・更新のみ」にする
- または `contact-config.php` を同期の除外対象に指定する

どちらかの対応をお願いします。

## うまくいかないときは

### フォームが「サーバー設定が未完了です」と表示する

`contact-config.php` が無いか、中身に不備があります。
ファイル名の綴り、設定項目のキー名（`mail_to` を `mail_too` と書いていないか等）を
確認してください。

### ページ全体が真っ白／500エラー

PHP のバージョンが 8.0 未満の可能性が高いです。手順0に戻って確認してください。

### 送信はできるがメールが届かない

1. 迷惑メールフォルダを確認する
2. `mail_from` が `@sunyutech.jp` のアドレスになっているか確認する
3. それでも届かない場合は、サーバーのメール送信機能が止められている
   可能性があります。お名前.com のサポートに「PHP の `mb_send_mail` で
   メールが送信されない」と問い合わせてください

### 詳しい原因を知りたい

不具合の内容はサーバーのエラーログに日本語で記録されます。
管理画面の「ログ」または公開ディレクトリの `error_log` を確認してください。

例:
```
contact.php: contact-config.php の内容が不正です: mail_to に有効なメールアドレスを設定してください
contact.php: レート制限の保存先が使えないため、レート制限なしで動作しています: /tmp/sunyutech-contact
contact.php: ハニーポットにより破棄しました ip=xxx.xxx.xxx.xxx
```
